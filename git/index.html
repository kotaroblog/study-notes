SVN 経験者のための Git 図解

見えるGit

コマンド1つで、ファイルとブランチが「どこからどこへ」動くのか。作業フォルダ・ステージ・ローカル・リモートの4か所を並べて、1ステップずつ見ていきます。

SVN から来た人がつまずく3つの違い

ここだけ先に押さえると、下の図が読みやすくなります。

違い 1

コミットは手元だけ。共有は push で

SVN の commit は「サーバーに送る」まで1回で済みます。Git は commit で手元に記録し、push で初めてリモートに送ります。

違い 2

ブランチは「コミットに貼る付箋」

フォルダをコピーするのではなく、どのコミットを指しているかの名札です。手元で一瞬で作れて、push するまで他の人には見えません。

違い 3

origin/main は「リモートの main の控え」

最後に fetch（または pull）したときに、リモートの main がどこを指していたかの控えで、手元にあります。取り直すまで古いままです。

場面1：機能ブランチを作って、main に入るまで

開発でいちばん多い流れです。途中で同僚の変更が先に main へ入る場面も入れて、ローカルとリモートのずれ方を見ます。

早見表：コマンドとデータの動き

この場面に出てきたコマンドだけをまとめています。

コマンド動きSVN だと
git cloneリモート → ローカル → 作業フォルダsvn checkout（履歴ごと手元に来る）
git switchローカル → 作業フォルダ（中身を入れ替える）svn switch
git add作業フォルダ → ステージsvn add に似ているが、変更のたびに必要
git commitステージ → ローカルsvn commit の「記録する」半分
git pushローカル → リモートsvn commit の「サーバーへ送る」半分
git fetchリモート → ローカル（控えだけ更新）svn status -u に近い
git pullリモート → ローカル → 作業フォルダsvn update
